# Media Security Lab 设计规格

## 1. 背景与目标

Media Security Lab 是一个运行在 Windows 和 macOS 上的桌面实验室工具。用户输入一个自己拥有或获授权测试的公开视频页面地址，工具在隔离 Chromium 中加载页面，观察媒体请求和播放管线，识别视频轨、音频轨、清单、Range 请求及 blob/MSE 来源，然后重放受控请求，判断现有防下载措施是否真正由服务端执行。

工具能够下载确认可访问的媒体轨、通过 FFmpeg 无损封装音视频、使用 ffprobe 验证文件，并输出中文安全报告。界面必须实时展示每个动作、输入变化、服务器响应和判定依据，使用户能够复核工具如何得出结论。

工具的成功标准不是“下载失败”，而是准确区分服务端拒绝、令牌失效、媒体加密、网络异常、解析器不支持和本地工具故障，避免把工具失败误判成防护有效。

## 2. 范围

第一版支持：

- 公开、无需登录即可播放的页面；
- 直接 MP4/WebM、基于 HTTP Range 的 MP4；
- 视频轨与音频轨分离的 MP4；
- HLS 清单与媒体分片；
- DASH 清单与媒体分片；
- 由 blob URL、MediaSource、Worker 或 Service Worker 隐藏实际地址的播放流程；
- HTTP 层的签名、有效期、Cookie、Referer、Origin、Range 和并发限制验证；
- FFmpeg 无损封装及 ffprobe 完整性验证；
- 本地测试历史、媒体文件、JSON 证据和 Markdown 报告。

第一版不包括：

- 账号登录、验证码、Cookie 导入或账号凭据收集；
- DRM 破解、许可证绕过或解密密钥提取；
- 批量爬取、站点遍历、视频 ID 枚举或搜索；
- 绕过服务端入侵防护；
- 云端上传或多人协作。

每次运行只处理用户明确输入的一个页面及该页面直接产生的媒体请求。

## 3. 技术路线

客户端采用 Electron、TypeScript 和 React。Electron 提供跨平台桌面外壳和固定版本 Chromium，Chrome DevTools Protocol（CDP）负责观察主页面、iframe、Worker、Service Worker 和网络事件。后台 Node.js 进程负责请求重放、流式下载、持久化和子进程管理。FFmpeg 与 ffprobe 作为按平台打包的 sidecar 二进制文件运行。

构建与打包采用 Electron Builder，目标包括：

- Windows x64；
- macOS x64；
- macOS arm64。

页面内容运行在独立、沙箱化的 WebContents 中，启用 `contextIsolation` 和 `sandbox`，关闭 `nodeIntegration`。目标页面不能直接调用文件系统、Node.js API 或 Electron IPC。渲染层只通过带类型约束的 preload API 与主进程通信。

## 4. 总体架构

```text
React Renderer
  ├─ 新建测试
  ├─ 页面与轨道视图
  ├─ 实时步骤流
  ├─ 安全测试矩阵
  └─ 下载与报告
          │ typed IPC
Electron Main
  ├─ Run Orchestrator
  ├─ Isolated Browser Controller
  ├─ CDP Capture Engine
  ├─ Media Correlator
  ├─ Probe Engine
  ├─ Streaming Downloader
  ├─ FFmpeg/ffprobe Adapter
  ├─ Evidence Store
  └─ Report Generator
          │
Local Target Lab
  ├─ 开放 Range
  ├─ Referer-only
  ├─ 短期签名
  ├─ 会话绑定
  ├─ Range 限制
  └─ 分片令牌
```

模块通过显式接口交换不可变的运行记录，避免网络捕获、下载和界面状态相互耦合。所有长任务均可取消，取消信号由 Run Orchestrator 统一传播。

## 5. 核心数据流

### 5.1 创建运行

用户填写页面地址和输出目录，选择自动模式或只分析模式。工具生成运行 ID，创建隔离 Session 和运行目录，然后写入第一条步骤事件。运行目录结构为：

```text
runs/<run-id>/
  evidence.json
  report.md
  requests/
  tracks/
  output/
  logs/
```

### 5.2 页面观察

Browser Controller 在隔离 WebContents 中导航到目标地址。CDP Capture Engine 启用目标自动附加，监听：

- `Target.*`：发现 iframe、Worker 和 Service Worker；
- `Network.*`：请求、响应、重定向、缓存和失败原因；
- `Runtime.*`：必要的只读探针结果；
- `Page.*`：导航和生命周期；
- `Media` 域：可用时读取播放器属性和事件。

对每个请求保存 URL 的脱敏副本、资源类型、发起目标、状态码、内容类型、内容长度、Content-Range、ETag、缓存状态和耗时。敏感查询值不进入普通日志，原始值仅保存在主进程当前运行的临时内存中用于重放，应用退出或运行结束后释放。

### 5.3 媒体发现与关联

Media Correlator 根据以下信号给请求评分：

- `Content-Type` 为视频、音频或流媒体清单；
- HTTP 206、Range、Content-Range、较大响应体；
- URL 扩展名或路径包含媒体编码标记；
- HLS/DASH 清单引用关系；
- MSE SourceBuffer MIME 与 codec；
- 请求时间和播放器播放时间的相关性；
- ffprobe 对少量合法样本的识别结果。

系统以 `MediaAsset` 表示一个可播放内容，以 `MediaTrack` 表示候选视频轨、音频轨或复合轨。音视频分离时，根据时长、时间基、内容 ID、清单关系和请求时间进行配对。自动选择最高质量候选，但界面允许用户更换轨道。

### 5.4 安全验证

Probe Engine 从已观察的成功请求生成受控变体，不猜测新资源 ID。默认矩阵包括：

1. 原始请求基线；
2. 删除 Cookie；
3. 删除全部查询参数；
4. 删除 Referer；
5. 删除 Origin；
6. 请求文件开头的短 Range；
7. 请求远离当前播放位置的中间和尾部 Range；
8. 请求 `0-文件结尾` 的完整 Range；
9. 最多四路的有限并发 Range；
10. 在可识别的有效期结束后重放。

每个变体记录请求头差异、状态码、响应类型、实际字节数、Content-Range、耗时和风险解释。探针默认只下载短范围；只有用户在当前运行中明确启动“完整下载验证”时才获取完整媒体。

判定规则以服务端证据为准：

- HTTP 401/403 且响应来自目标服务，判为权限拒绝；
- 返回目标媒体字节，判为访问成功；
- CORS 阻止页面读取但后台客户端可获得字节，判为可下载；
- DNS、TLS、超时、进程失败或未知格式，判为测试异常；
- DRM/加密媒体被识别但未解密，判为加密有效性待许可证策略验证，不尝试绕过。

### 5.5 下载与合并

Streaming Downloader 使用后台 HTTP 客户端发送已批准的请求变体，响应直接写入临时文件。下载器支持：

- 单次完整 Range；
- 服务端限制响应大小时的顺序 Range；
- ETag/Last-Modified 一致性检查；
- Content-Range 连续性与总长度检查；
- 有限并发、重试、取消和断点续传；
- SHA-256 与实际字节数记录；
- 原子重命名，防止未完成文件被误认为成功。

音视频轨下载完成后，FFmpeg Adapter 使用 stream copy 重新封装。ffprobe 验证输出文件的轨道数、编码、分辨率、时长和容器。视频轨或音频轨不完整时禁止生成“成功”结果。

## 6. 全过程可视化

界面中心是不可变的 `RunEvent` 步骤流。每个后台动作先写事件，再更新聚合状态。事件字段包括：

- 时间戳和递增序号；
- 阶段：浏览器、CDP、识别、探针、下载、FFmpeg、验证、报告；
- 动作名称和执行目的；
- 输入摘要与脱敏后的请求变化；
- 状态：等待、运行、成功、拒绝、警告、失败、取消；
- 服务器或本地工具返回的关键证据；
- 判定规则及其解释；
- 关联请求、轨道和输出文件 ID。

界面按阶段展示时间线。用户可展开任一事件查看：

- 工具准备执行什么；
- 修改了哪些请求字段；
- 为什么执行该测试；
- 服务端实际返回什么；
- 该结果支持或不支持什么结论。

请求差异使用左右对比视图，只显示发生变化的头和查询参数。URL、Cookie、Authorization、签名和令牌默认脱敏。用户可以在本地临时查看原始值，但导出的普通报告始终脱敏。

下载区显示每条轨道的已接收字节、总字节、速度、Range 区间、重试次数、ETag 和磁盘路径。FFmpeg 区显示结构化阶段和可展开的原始日志。报告结论可以点击回到产生该结论的步骤事件。

## 7. 界面结构

### 7.1 新建测试

- 页面 URL；
- 输出目录；
- 运行模式：只分析、标准安全验证、完整下载验证；
- 最大并发，默认 4；
- 请求和磁盘大小上限；
- 用户确认目标属于自己或已获授权。

### 7.2 运行工作台

- 左侧：隔离页面预览和运行控制；
- 中间：实时步骤流；
- 右侧：媒体资产、轨道和安全测试矩阵；
- 底部：下载、FFmpeg 和错误日志抽屉。

### 7.3 结果页

- 总体结论及置信度；
- 已发现的播放架构图；
- 可下载性和访问控制矩阵；
- 下载及合并文件；
- 修复优先级；
- JSON/Markdown 导出。

## 8. 持久化模型

SQLite 保存运行索引和结构化结果，媒体、日志和报告保存在运行目录。核心实体包括：

- `TestRun`：目标、模式、状态、时间和输出目录；
- `RunEvent`：全过程事件；
- `CapturedRequest`：脱敏请求和响应元数据；
- `MediaAsset`：内容级聚合；
- `MediaTrack`：轨道编码、长度、来源和选择状态；
- `ProbeResult`：请求变体和结果；
- `DownloadArtifact`：文件、哈希和完整性；
- `Finding`：风险、证据、置信度和修复建议。

数据库不保存明文 Cookie、Authorization 或签名令牌。

## 9. 错误处理

- 导航失败：保留已捕获请求并明确标记页面加载失败；
- 页面持续运行：达到用户配置的观察时间后允许手动结束发现；
- URL 过期：记录基线失败，提示重新加载页面获得新基线；
- 轨道配对不确定：禁止自动合并，要求用户选择；
- Range 不连续：删除临时结果并保留证据；
- ETag 变化：停止下载，避免拼接不同版本；
- 磁盘不足：下载前检查空间，写入失败立即停止；
- FFmpeg/ffprobe 不可用：启动自检失败，禁止进入合并阶段；
- 应用崩溃：下次启动将未完成运行标为中断，可从合法断点恢复；
- 用户取消：终止页面、网络请求和子进程，保留已生成报告和临时文件清单。

所有失败必须产生面向用户的解释和可展开的技术原因。

## 10. 本地靶场

项目包含只监听本机的测试服务器和固定媒体样本。每种场景有明确预期：

- `open-range`：删除参数及完整 Range 均成功；
- `referer-only`：缺少 Referer 时拒绝，但伪造 Referer 可访问，报告弱防护；
- `signed-url`：签名、资源、过期时间任一变化均拒绝；
- `session-bound`：签名与会话不匹配时拒绝；
- `range-capped`：单次响应受限，重复 Range 仍可完成，报告仅降低速度；
- `segment-token`：每个分片独立令牌，越过预取窗口时拒绝；
- `encrypted-placeholder`：识别加密元数据并停止解密流程。

靶场用于回归验证工具的判定逻辑，也用于比较用户优化前后的效果。

## 11. 测试策略

- 单元测试：URL 脱敏、请求变体、Range 规划、Content-Range 解析、轨道配对、风险规则；
- 集成测试：针对每个靶场策略执行捕获、探针、下载和报告；
- 媒体验证测试：MP4 单轨、MP4 分轨、HLS、DASH 的发现和 FFmpeg 封装；
- 故障测试：超时、断连、ETag 变化、短响应、磁盘不足和 FFmpeg 失败；
- Electron 端到端测试：新建运行、观察步骤、展开证据、取消、恢复和导出；
- 打包验证：Windows x64、macOS x64 和 macOS arm64 的启动自检及 sidecar 可执行性。

关键验收标准：

1. 所有后台动作都能在界面步骤流中找到对应事件；
2. 用户能从每个风险结论回到完整证据链；
3. 靶场每种策略的实际判定与预期一致；
4. 分离音视频能够完整下载、无损合并并通过 ffprobe；
5. 下载失败不会在报告中自动变成“安全”；
6. 明文凭据不会进入数据库、普通日志或导出报告；
7. 取消运行后不再产生网络请求或遗留后台进程。

## 12. 风险与限制

- Chromium 或目标站点更新可能改变 CDP 行为，需要维护捕获适配器；
- 加密、专有协议或浏览器之外的原生播放链路只能识别，不能下载；
- 无法下载只代表定义的测试矩阵未成功，不代表不存在其他方法；
- Referer、Origin、CORS、blob URL 和音视频分离不是可靠权限边界；
- Range 限制、分片令牌和速率控制只能降低自动下载速度；
- 已授权播放的高价值内容仍需 DRM、水印和服务端审计组合防护；
- FFmpeg 二进制的分发方式必须满足所选构建及编解码配置对应的许可证要求。
